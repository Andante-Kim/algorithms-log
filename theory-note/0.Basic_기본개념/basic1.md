# 0.시간, 공간 복잡도

## 시간 복잡도 (Time Complexity)

**시간 복잡도**: 입력의 크기와 문제를 해결하는데 걸리는 시간의 상관관계

**빅오 표기법** : 주어진 식을 값이 가장 큰 대표항만 남겨서 나타내는 방법
* O(N): **5N**+3, **2N**+1-10lgN, **10N**
* O($N^2$): **$N^2$**+2N+4, **$6N^2$**+20N+10lgN
* O(NlgN): NlgN+20N+10, 5NlgN+6
* O(1): 5, 16, 36

![Alt text](https://i.ytimg.com/vi/47GRtdHOKMg/maxresdefault.jpg)

| N의 크기 | 허용 시간 복잡도 |
|---|---|
| N ≤ 11 | O(N!) |
| N ≤ 25| O($2^N$) |
| N ≤ 100| O($N^4$) |
| N ≤ 500 | O($N^3$)|
| N ≤ 3000 | O($N^2\lg N$)|
| N ≤ 5000 | O($N^2$)|
| N ≤ 1,000,000| O(NlgN)|
| N ≤ 10,000,000 | O(N)|
| 그 이상 | O(lgN), O(1) |

# 1. 정수 자료형

char 자료형 : 1 byte = 8 bit
| $-2^7$ | $2^6$ | $2^5$ | $2^4$ |$2^3$ | $2^2$ | $2^1$ | $2^0$ |
|---|---|---|---|---|---|---|---|
|0|0|0|0|1|0|0|1|

unsigned char 자료형의 범위: $0 \sim 2^0 + 2^1 \cdots +2^7(=2^8-1=255)$

char 자료형의 범위 = $-2^7(=-128) \sim 2^0+ 2^1 \cdots +2^7(=2^7-1=127)$

short (2 byte): $2^15 -1(=32767)$

int (4 byte): $2^{31} -1(\doteqdot 2.1 \times 10^9)$

long long(8 byte): $2^{63} -1(\doteqdot 9.2 \times 10^{18})$

> 정수를 표현할 때 주로 int나 long long을 쓰는데 int가 long long보다 연산 속도나 메모리 모두 우수하지만 80번째 피보나치 수를 구하는 문제와 같이 int 자료형이 표현할 수 있는 범위를 넘어서는 수를 저장해야 하면 반드시 long long 자료형을 사용해야 한다.

## Integer Overflow

: 자료형의 범위에 맞지 않게 계산을 수행할 경우 발생하는 오류
```C
int main(void) {
    int a = 20000000000 * 2;
    cout << a;
}
/***result***
-294967296
*************/
```

# 2. 실수 자료형

: 2의 음수 거듭제곱을 이용해 임의의 실수를 2진수로 나타낼 수 있다. (e. $2^{-1}=0.5,\ 2^{-2}=0.25, \cdots$)

IEEE-754 format
* sign field : 해당 수가 음수인지 양수인지 저장하는 필드
* exponent field : 과학적 표기법에서의 지수를 저장하는 필드
* fraction field : 유효숫자 부분을 저장하는 필드

float (4 byte) : sign(1), exponent(8), fraction(23)

double (8 byte) : sign(1), exponent(11), fraction(52)

**실수의 성질**
1. 실수의 저장/연산 과정에서 반드시 오차가 발생할 수 밖에 없다.
    * float는 유효숫자가 6자리 -> 상대 오차 $10^{-6}$까지 안전 (m. 원래 참 값이 1이라고 할 때 $1-10^{-6}$에서 $1+10^{-6}$ 사이의 값을 가지는게 보장됨. 즉 오차가 생기는 것 자체를 막을 수는 없지만 오차가 어느 정도인지 알수 있다.)
    * double은 유효숫자가 15자리 -> 상대 오차 $10^{-15}$까지 안전
    * 두 자료형의 상대 오차 허용 범위 차이가 굉장히 크기 때문에, 실수 자료형이 필요하면 꼭 float 대신 double을 써야한다.
    * 실수 자료형은 필연적으로 오차가 있으므로 실수 자료형이 필요한 문제면 보통 문제에서 *"절대/상대 오차를 허용한다"*는 단서를 준다. (그런 표현이 없다면 대부분의 문제는 모든 연산을 정수에서 해결할 수 있음)
2. double에서 long long 범위의 정수를 함부로 담으면 안된다.
    * double은 유효 숫자가 15자리, long long은 유효 숫자가 최대 19자리이므로, $10^{18}+1$과 $10^{18}$구분할 수 없고 그냥 같은 값으로 저장된다. 
    * 즉, double에 long long 범위의 정수를 담을 경우 오차가 섞인 값이 저장될 수 있다.
    * 다만, int는 최대 21억이기 때문에, double에 담아도 오차가 생기지 않는다.
3. 실수를 비교할 때는 등호를 사용하면 안된다. 
    * 오차 때문에 두 실수가 같은지 알고 싶을 때에는 둘의 차이가 아주 작은 값, 대략 $10^{-12}(=1e-12)$이하면 동일하다고 처리하는게 안전하다.
